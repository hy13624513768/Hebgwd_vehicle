# 代码加固与后续开发说明

本轮保留现有 FastAPI + SQLAlchemy + Vue 的分层，优先修复权限、状态流转、数据写入与失败恢复，不补造历史数据、不重做未完成业务页面。

## 模块职责

| 位置 | 职责 |
| --- | --- |
| `backend/app/api/v1/` | HTTP 参数、访问控制、事务提交、响应转换 |
| `backend/app/core/data_scope.py` | 车间数据范围与对象访问校验，列表、统计、导出复用 |
| `backend/app/core/datetime_utils.py` | UTC 归一化、上海自然日查询边界 |
| `backend/app/schemas/patch.py` | PATCH 显式空值约束，区分不修改与清空字段 |
| `backend/app/services/trip_service.py` | 派车状态机、时间范围、车辆/驾驶员引用、占用冲突 |
| `backend/app/services/trip_acl.py` | 申请人、驾驶员、管理人员各自的可见/可修改范围 |
| `backend/app/services/kunlun_balance_service.py` | 加载本地昆仑余额脚本并原子更新余额数据 |
| `backend/app/services/fuel_sync_service.py` | 后台线程执行同步并输出进度流 |
| `backend/app/services/fuel_analysis_service.py` | 油料分析计算，与 API 路由解耦 |
| `backend/app/services/settlement_recognition_service.py` | 识别成功提交、失败保存状态并保留旧明细 |
| `backend/tests/test_hardening.py` | 隔离数据库的业务回归测试 |
| `frontend/src/api/` | HTTP 调用、车辆分页加载、导航版本传递 |
| `frontend/src/lib/tripWorkflow.ts` | 前端派车状态选项；后端仍是最终校验来源 |

新增业务规则优先放入服务，不在页面、路由和脚本中各实现一份。暂不批量移动现有页面，避免无必要的路径变更。

## 本轮行为变化

- 车间主任/管理员的车辆、驾驶员、派车、维修、油料查询与操作按车间限制；未分配车间不代表全段权限。驾驶员输出隐藏证件与健康资料等敏感字段。共享油卡主数据写入和全段同步需要段级账户管理权限。
- 驾驶员绑定账号必须存在、属于驾驶员角色且车间一致；批量生成账号同步填写绑定关系，并跳过已绑定人员。
- 派车状态只允许：待审批 → 已批准/驳回/取消，已批准 → 执行中/取消，执行中 → 完成/取消。结束状态不重新开启，只允许备注调整；驾驶员不能自行审批或改派。批准前校验车辆、驾驶员和时段冲突。
- PostgreSQL 派车通过资源行锁串行检查冲突；SQLite 测试不证明生产并发行为，需要上线前进行 PostgreSQL 并发验证。
- 启动不再重置已有账号角色、显示名称和车间归属，不再删除或重建旧业务表。运行时迁移只补列/索引；无法兼容的旧结构应备份后显式迁移，不静默删除数据。
- 油卡余额按钮及请求契约保持不变，底层改为本地 `获取油卡余额.py` 的昆仑司机卡接口；按卡更新当前余额，单次写入事务失败整体回滚。旧 95504 客户端已移除。
- 昆仑余额接口只提供当前余额，不提供加油流水；已有流水数据及其查询页面保持原样，本次余额同步不会新增流水。
- 油料分析按车牌/卡号区分数据，缺失里程时百公里油耗返回空值，不伪造为零。
- 导航全量保存携带内容版本 `revision`，拒绝覆盖他人新版本；删除权限由后端校验。保存冲突后需重新加载并核对修改。
- 维修识别失败保留上一次成功明细，并记录失败状态。同步识别接口在线程池执行；尚未改造成持久化任务队列。
- 维修上传限制后缀与单文件大小；维修汇总在数据库中分页和聚合。当前文件校验不替代内容检测，也不覆盖网关请求体大小限制。
- 车辆统计/选择改为逐页读取，维修汇总增加分页；这不是所有业务列表的统一分页改造。

## 配置与升级注意

1. 前后端需一起更新，尤其是导航 `revision` 与油耗空值显示。
2. 本地默认加载项目同级 `中国石油/获取油卡余额.py`，并由该脚本使用同目录的 `登录.py`、`config.json` 和 `token.json`。位置不同时设置 `KUNLUN_BALANCE_SCRIPT`；不要提交凭据与 Token。
3. `MAX_UPLOAD_MB` 默认 50，必须为正数。真实业务环境设置 `DEMO_SEEDING_ENABLED=false`，避免缺少业务数据的表被演示数据填充。
4. 使用现有数据前先备份。重复的驾驶员账号绑定可能使新增唯一索引失败，需人工核对；运行时迁移不会自行丢弃重复数据。
5. 旧记录只有车间名称、没有 `workshop_id` 时，部分列表支持按名称读取，但修改仍要求明确归属。由段级管理员核对补齐，不自动猜测到默认车间。
6. 余额同步依赖本地昆仑脚本及其 Python 依赖；启动后端的本地 Python 环境必须安装 `backend/requirements.txt`。
7. 不再启动自动清理历史费用表。历史 Excel 导入脚本可能仍针对旧结构，执行前必须核对字段并使用试跑/备份；本轮没有统一这些历史导入流程。

## 验证方式

在 `backend` 目录执行：

```powershell
python -m unittest discover -s tests -v
python smoke_test.py
python -m compileall -q app smoke_test.py tests
```

单元/接口测试使用内存 SQLite 和合成数据，不执行应用启动、不访问外部油料或识别平台。冒烟测试使用自动创建和清理的临时数据库，验证完整启动、健康/就绪检查、滑块登录与当前用户接口，不使用项目数据库。

在 `frontend` 目录执行：

```powershell
npm run build
```

本轮未触发真实昆仑平台登录或短信验证码，也未验证真实 AI 识别和浏览器端到端交互。

## 暂缓事项

- `MaintenanceRecord` 台账与 `RepairRecord/RepairSettlement` 维修结算的统一口径、历史映射和最终业务流程。
- 不完整的加油登记表单、占位功能、缺失里程、车辆与卡号映射等业务补全。
- 全部列表的统一分页/搜索、超大数据量统计 API、前端端到端测试。
- 带版本的正式数据库迁移体系、跨实例任务队列、文件存储生命周期与孤立文件清理。
- 昆仑接口当前仅同步余额；加油流水新接口、数据更正/撤销策略和定期对账仍需后续确定。
